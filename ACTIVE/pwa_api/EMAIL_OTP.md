# Email OTP — общий вход PWA и mobile

Этот этап добавляет вход по одноразовому коду и безопасную привязку email,
не меняя существующий вход через Telegram.

## Переменные окружения

- `EMAIL_OTP_SECRET` — случайная строка не короче 32 символов;
- `EMAIL_SMTP_HOST` — SMTP-сервер;
- `EMAIL_SMTP_PORT` — порт SMTP over TLS, по умолчанию `465`;
- `EMAIL_SMTP_USER` — логин SMTP;
- `EMAIL_SMTP_PASSWORD` — пароль SMTP;
- `EMAIL_FROM` — адрес отправителя, по умолчанию равен `EMAIL_SMTP_USER`.

Код не запускается в production без отдельного `EMAIL_OTP_SECRET`. Коды не
пишутся в логи и хранятся в базе только как HMAC-хеш. Срок жизни — 10 минут,
максимум пять попыток, успешный код используется один раз.

## Контракт

1. `POST /auth/email/request` принимает `email`, необязательное `name` и
   `client_scope`: `pwa` (по умолчанию) либо `mobile`.
2. `POST /auth/email/verify` принимает `challenge_id` и шестизначный `code`.
3. Если первый запрос сделан с действующим Bearer-токеном, подтверждённый email
   привязывается именно к этому PWA/Telegram-аккаунту.
4. Без Bearer-токена существующий email выполняет вход, новый создаёт отдельный
   PWA-аккаунт без доступа к Telegram-прогрессу до безопасной привязки.
5. Для `client_scope=mobile` неподключённый email получает защищённый PWA-токен
   со статусом `telegram_required`, а не теряет уже подтверждённую сессию.
6. Клиент создаёт принадлежащую этому аккаунту сессию через
   `POST /auth/telegram-link/init`, открывает существующий deep-link бота и
   опрашивает `GET /auth/telegram-link/check`.
7. После подтверждения ботом API атомарно записывает `pwa_users.tg_id`. Если этот
   Telegram уже принадлежит другому аккаунту, API отвечает `409` и не объединяет
   данные автоматически.
8. При наличии записи в `participants` API выдаёт mobile-токен. Иначе возвращает
   `activation_required`; после активации `POST /auth/mobile-session` обновит
   сохранённую сессию без повторного ввода email.

После привязки PWA, приложение, миниапп и бот используют один Telegram ID и одни
реальные таблицы программы. Email становится дополнительным способом входа, а не
отдельным владельцем прогресса. Код бота и миниаппа для этого потока не меняется.

## Безопасное первое подключение

Действующий участник сначала один раз входит через Telegram. Затем в профиле или
на экране входа, пока mobile-токен ещё сохранён, запрашивает код на свой email.
После подтверждения email привязывается к тому же `pwa_users.tg_id`. В дальнейшем
можно входить по email без открытия Telegram.

Нельзя автоматически объединять аккаунты по совпадению с `users.email`: старые
адреса в этой таблице не проходили подтверждение.
